0. ПОРЯДОК ПРИМЕНЕНИЯ. ЧИТАТЬ ДО ТОГО, КАК ЧТО-ТО ЖАТЬ

Правильная последовательность:

  1. Windows Update: все обновления, перезагрузка
  2. BIOS / UEFI: обновить прошивку, затем настройки (разделы 6, 7)
  3. Драйверы чипсета и GPU с сайта производителя, не через Windows Update
  4. Перезагрузка, проверка стабильности
  5. Точка восстановления ПОСЛЕ всех обновлений
  6. WinPulse: режим (LITE / MINIMUM / MEDIUM / WORK / MAXIMUM)
  7. Перезагрузка
  8. Ручные шаги из этого файла (разделы 2-5, 8-11)
  9. Сторонние утилиты (разделы 10, 12)
  10. Замеры и проверка (раздел 15)

ОБНОВЛЕНИЯ ПЕРВЫМИ. НАСТОЙЧИВО. - Windows сама сбрасывает часть твиков при обновлениях: VBS, Defender, GameDVR, план питания. Применить твики и сразу получить обновление - потерять половину работы и не понять, что именно откатилось. - BIOS и драйверы обновляются ради СТАБИЛЬНОСТИ, не скорости. Твики поверх кривого драйвера маскируют проблему, а не решают её. - Точка восстановления нужна ПОСЛЕ обновлений. Точка "до обновления" вернёт тебя назад вместе с самими обновлениями.

BITLOCKER / DEVICE ENCRYPTION. ЕСЛИ ДИСК ЗАШИФРОВАН: Сохрани ключ восстановления ДО любых твиков: manage-bde -protectors C: -get Правки BCD меняют измерения TPM, и BitLocker может запросить ключ при следующей загрузке. WinPulse проверяет шифрование при старте и перед BCD-блоками предлагает приостановить защиту на одну перезагрузку: manage-bde -protectors -disable C: -RebootCount 1 Защита включится сама после ребута. Без ключа на руках не начинай.

Почему именно так: - WinPulse ведёт ЖУРНАЛ каждого изменённого значения и умеет откатывать только своё. Сторонние оптимизаторы пишут мимо журнала. - Если сначала прогнать Chris Titus Tool или O&O, а потом WinPulse, откат WinPulse вернёт систему НЕ в исходное состояние, а в состояние "после чужих твиков". Искать причину потом больно. - Точка восстановления ловит и чужие изменения тоже. WinPulse создаёт её принудительно перед любым режимом. Не отключай System Restore.

Первый прогон WinPulse рекомендуется в песочнице: winpulse.bat /dryrun Она покажет план выбранного режима и результаты гвардов, не тронув систему. Если вывод чистый - можно применять по-настоящему.

Если ты уже применял сторонние тулзы ДО WinPulse: - создай точку восстановления вручную перед запуском WinPulse; - помни, что полный откат WinPulse не вернёт то, что меняли они; - список пересечений смотри в Main\EXTERNAL_TOOLS.txt.

  • План питания: какой выбирать Win+R -> powercfg.cpl
    Обычный случай:                High Performance (ставит WinPulse)
    Ryzen 3000 и новее:            AMD Ryzen High Performance, если есть

Про Ultimate Performance честно: - это НЕ "другой эффект". Внутри него core parking уже отключён, min processor state 100%, USB suspend off, disk idle never, PCIe ASPM off. То есть пакетом то же, что мы крутим точечно. - надёжнее он потому, что схема определена Microsoft и откат - это переключить план обратно, а не откатывать десяток значений. - на Ryzen с CPPC preferred cores принудительные 100% могут СНИЗИТЬ одноядерный boost: выше idle-температура, меньше запаса. - на ноутбуках и Modern Standby системах схему не включай вообще.

В WinPulse это блок EXP_ULTIMATE в Experimental, с жёсткой блокировкой для ноутбуков и питания от батареи.

Создать вручную, если хочешь без WinPulse: powercfg -duplicatescheme e9a42b02-d5df-448d-aa00-03f14749eb61 Удалить созданную схему: powercfg /list powercfg /delete <GUID новой схемы>

    ВАЖНО, не делай это вслепую на всех дисках:
      Игровой ПК:   снять индексацию с игровых дисков можно.
      Рабочий ПК:   ОСТАВИТЬ. Режим WORK ставит WSearch в delayed-auto
                    именно ради поиска. Сняв индексацию, ты обнулишь смысл
                    этого твика и получишь медленный поиск в Outlook/Explorer.
  • Дефрагментация и TRIM. Тут вся суть путаницы HDD/SSD Win+R -> dfrgui

Как это работает на Windows 10/11: - "Оптимизация дисков" для SSD выполняет RETRIM, а не дефрагментацию. Полноценный дефраг SSD система делает только при необходимости (сильная фрагментация метаданных, VSS). - Для HDD это обычная дефрагментация, и она НУЖНА. - Расписание по умолчанию еженедельное и трогает оба типа носителей.

Что делать: [ ] Оставить расписание включённым, если в системе есть HDD [ ] Оставить расписание включённым для SSD ради планового Retrim [ ] НЕ отключать службу defragsvc "ради SSD"

    WinPulse и defragsvc:
      - по умолчанию службу НЕ трогает;
      - блок DEFRAG применится только если: все диски SSD, неизвестных
        дисков нет, включён Advanced Mode и введён YES;
      - при отключении службы умирает и плановый Retrim. Тогда делай вручную:
          defrag C: /L        (retrim SSD)
          defrag C: /O        (оптимизация по типу носителя)
      - проверка TRIM:
          fsutil behavior query DisableDeleteNotify
        0 = TRIM включён. WinPulse выставляет 0 в блоке обслуживания.

Итог: отключение defragsvc - не "оптимизация SSD", а осознанный отказ от планового обслуживания. Если не понимаешь зачем - не отключай.

  • Автозагрузка. GUIDE-SAFE для апдейтеров, GUIDE-COND для остального Win+R -> taskmgr -> вкладка "Автозагрузка" Отключать через этот переключатель, а НЕ удалять ключи Run.

Почему именно так: Диспетчер задач не удаляет запись, а ставит флаг в Explorer\StartupApproved. Это обратимо, видно в GUI, и приложение не пересоздаёт запись при следующем запуске. Удаление Run - это то, чем грешат "оптимизаторы", после которого не вернуть тачпад или OneDrive.

Что можно отключать почти без риска: Adobe Acrobat Updater, Google Update, Java Update Scheduler, iTunesHelper, CCleaner Monitoring, Skype, Spotify Web Helper, Teams Machine-Wide Installer Что НЕ отключать без понимания: антивирус, аудио-панель, тачпад, облачная синхронизация, утилиты производителя ноутбука (горячие клавиши, управление зарядкой)

Как найти реальных виновников, а не гадать: WinPulse -> [N] Время загрузки События 101/102/103 называют приложения, драйверы и службы с временем в миллисекундах. Ориентируйся на них, а не на списки "известных вредителей" из интернета.

Глубже Диспетчера задач (GUIDE-COND): Win+R -> taskschd.msc -> Библиотека планировщика Ищи задачи с триггером "При входе в систему" / "При запуске" от не-Microsoft издателей: Google, Adobe, NVIDIA, Office. Отключай через ПКМ -> Отключить, это обратимо. Именно здесь прячется основная масса апдейтеров, Диспетчер задач их не показывает вообще.

      Win+R -> shell:startup  и  shell:common startup
      Убери лишние ярлыки. Тоже обратимо: ярлык можно вернуть.

Что смотреть, но НЕ трогать (GUIDE-AVOID): Winlogon\Userinit и Shell, Session Manager\BootExecute, AppInit_DLLs, Active Setup, UserInitMprLogonScript. Сломанный Userinit = невозможно войти в систему вообще, придётся лезть в среду восстановления. Это либо системно-критичное, либо индикатор малвари. Только диагностика, не "оптимизация".

Честно: Steam, Discord, OneDrive пересоздают запись автозапуска при следующем старте. Надёжнее выключить автозапуск в настройках самого приложения, а не бороться с записью.

  • Аудио-улучшения (audio enhancements) Win+R -> mmsys.cpl -> Воспроизведение -> ПКМ по устройству -> Свойства -> вкладка Дополнительно или Улучшения -> снять "Включить дополнительные средства обработки звука" / "Enable audio enhancements" -> применить, повторить для каждого устройства вывода

Почему вручную: настройка живёт в per-endpoint FxProperties и зависит от аудиодрайвера. Универсального ключа реестра нет, поэтому WinPulse этот пункт помечает SKIP, а не пишет фиктивный параметр. Что даёт: убирает программную обработку (эквалайзер, loudness, виртуальный surround), снижает задержку вывода на 5-20 мс. Что теряешь: улучшения звука от вендора, если они тебе нравились. Как вернуть: поставить галку обратно там же.

3. СЕТЕВОЙ АДАПТЕР (devmgmt.msc)

Ethernet автоматизирован: блок NIC_DRIVER, 14 операций, режим MAXIMUM. Он ищет имена значений по алиасам, потому что NDIS-ключи идут со звёздочкой, а вендорские Realtek без неё и иногда называются иначе. Отсутствующие значения не создаются: выдуманный ключ драйвер может проигнорировать.

Что делает NIC_DRIVER сам:
  *InterruptModeration = 0      модерация прерываний
  *EEE или EEE = 0              Energy Efficient Ethernet
  AdvancedEEE = 0               расширенный EEE
  EnableGreenEthernet = 0       Green Ethernet, у Realtek именно так
  GigaLite = 0                  Gigabit Lite, у Realtek именно так
  PowerDownPll = 0              усыпление PLL
  SelectiveSuspend или PowerSavingMode = 0
  *PMARPOffload = 0             ARP offload
  *PMNSOffload = 0              NS offload
  *RscIPv4 и *RscIPv6 = 0       склеивание пакетов
  ASPM = 0                      энергосбережение PCIe
  CLKREQ = 0                    запрос тактирования PCIe
  *RSS = 1                      включение, если драйвер поддерживает

Гварды: только физический Ethernet. Три фильтра: Get-NetAdapter -Physical, MediaType 802.3, совпадение NetCfgInstanceId с веткой реестра. WiFi, виртуальные, TAP и VPN адаптеры не проходят. На ноутбуке требуется YES.

Что остаётся вручную: [ ] Speed & Duplex -> Auto Negotiation Принудительно 1 Gbps Full ставь только если автосогласование ломается. Для 1000BASE-T согласование обязательно по стандарту, форс его отключает и может дать duplex mismatch и потери под нагрузкой. Признак рассогласования: Get-NetAdapter показывает LinkSpeed 100 Mbps, а *SpeedDuplex выставлен в 6. Роутер при этом может уйти в half duplex, отсюда коллизии и рваная скорость. Проверить FullDuplex обязательно. Кабель: для 1 Гбит нужны четыре пары, Cat5e или Cat6. Двухпарный кабель поднимет только 100 Мбит, и форс гигабита на нём всегда даёт потери. [ ] Flow Control -> на своё усмотрение Отключение убирает pause-фреймы и снижает задержку, но на дешёвом роутере может дать дропы под нагрузкой. WinPulse его не трогает сознательно. Меняй только если замерил разницу. [ ] Jumbo Frame -> 1514, если весь путь не поддерживает больше [ ] Receive и Transmit Buffers -> по умолчанию достаточно Увеличение помогает при тяжёлом трафике, для игр разница в пределах шума, а nonpaged pool расходуется больше. [ ] Контрольные суммы и LSO -> ОСТАВИТЬ ВКЛЮЧЁННЫМИ Их отключение перекладывает работу на CPU и режет пропускную способность. Частая ошибка чужих оптимизаторов.

RSS может отсутствовать физически: У большинства Realtek PCIe GbE, RTL8168/8111/8169, одна аппаратная очередь приёма. Драйвер не публикует *RSS и *NumRssQueues, а Get-NetAdapterRss возвращает пустоту. Это ограничение чипа, не настройка. netsh rss=enabled в таком случае работает вхолостую. Проверить: Get-NetAdapterRss | Format-List Name,NumberOfReceiveQueues

Посмотреть реальные имена значений своей ветки: Get-ChildItem "HKLM:\SYSTEM\CurrentControlSet\Control\Class\{4d36e972-e325-11ce-bfc1-08002be10318}" | ForEach-Object { $p = Get-ItemProperty $_.PSPath; "$($_.PSChildName) $($p.DriverDesc)" } Затем Get-ItemProperty по нужному номеру и Format-List *

WiFi остаётся ручным, см. раздел 17.

QoS, если есть gpedit.msc (Pro/Enterprise): Win+R -> gpedit.msc -> Конфигурация компьютера -> Административные шаблоны -> Сеть -> Планировщик пакетов QoS -> "Ограничить резервируемую пропускную способность" -> Включено -> 0

Миф-контроль: по умолчанию Windows НЕ резервирует 20% канала постоянно. Резерв работает только при активных QoS-приложениях. Твик безвреден, но и прироста от него обычно нет.

5. СИСТЕМНЫЕ УСТРОЙСТВА: HPET

Для обычного профиля оставь HPET и загрузочные таймеры в состоянии Windows. HPET в диспетчере устройств, источник счётчика времени и периодический тик ядра — три разных механизма. disabledynamictick управляет пропуском тиков при простое. useplatformclock меняет выбор источника счётчика, useplatformtick — выбор платформенного тика. TSC sync policy относится к синхронизации аппаратных счётчиков процессора. Изменения BCD требуют перезагрузки. GlobalTimerResolutionRequests и запросы разрешения таймера от приложений рассматривай отдельно. LatencyMon измеряет задержки драйверов; для сравнения плавности игры дополнительно запиши время кадров в одной сцене. Наблюдение автора WinPulse: при экспериментах с disabledynamictick и отключением HPET на его ПК хуже работал буст ядер, снизилась отзывчивость, возникал BSOD. Какой именно параметр вызвал сбой, отдельно не установлено. Если раньше менял это через WinPulse, используй откат группы B для записанных BCD-параметров. Устройство HPET, отключённое вручную, включается обратно в диспетчере устройств. Перед проверкой запиши исходное состояние и проверь доступность ключа восстановления BitLocker. Справка Microsoft: https://learn.microsoft.com/windows-hardware/drivers/devtest/bcdedit--set

6. BIOS / UEFI

Только из BIOS. Из Windows недоступно. Вход: Del / F2 / F10 при старте (зависит от платы).

Обязательное для игрового ПК:
  [ ] Above 4G Decoding            -> Enabled
  [ ] Re-Size BAR Support (SAM)    -> Enabled
  [ ] XMP / DOCP / EXPO            -> Enabled (профиль, не ручной разгон)
  [ ] Global C-State Control       -> см. ниже, НЕ однозначно
  [ ] Precision Boost Overdrive    -> Enabled (AMD, если охлаждение адекватное)
  [ ] CPU Load Line Calibration    -> Regular / Level 3 (не максимум)

Про C-State в BIOS: Отключение поднимает idle-температуру и энергопотребление, но убирает задержки выхода из глубоких состояний. На десктопе с хорошим охлаждением это может дать более стабильный frametime. На ноутбуке - перегрев и минус автономность. WinPulse имеет отдельный experimental-блок для C-states с жёсткой блокировкой на ноутбуках. BIOS-вариант делай вместо него, не вместе.

Опциональное:

На ПК автора разница во времени загрузки Windows составила около 0,3 с, а стабильность ухудшилась. Это наблюдение одной системы. ВАЖНЫЙ КОНФЛИКТ, читать обязательно: Блок POWER_HIBER (powercfg -h off) отключает Windows Fast Startup. То есть WinPulse ускоряет POST и одновременно выключает самый быстрый способ загрузки ядра Windows. На HDD разница большая. Это осознанный выбор, не баг: Fast Startup ломает корректную реинициализацию драйверов после "выключения", мешает обновлениям и dual-boot. Если нужен именно быстрый старт на HDD и понимаешь последствия - просто не подтверждай отключение гибернации, блок POWER_HIBER пропустится. BIOS-настройки работают независимо от него. То же касается Chris Titus Tool: его Hibernation - Disable работает против быстрого старта Windows, см. EXTERNAL_TOOLS.txt.

Как замерять: WinPulse -> [N] Время загрузки -> событие 100 BootDuration / MainPathBootTime / BootPostBootTime в миллисекундах. ВНИМАНИЕ: POST в эти цифры НЕ входит, он происходит до загрузчика Windows. Эффект BIOS-настроек замеряй секундомером от кнопки питания до появления логотипа загрузчика.

7. РАЗГОН ПАМЯТИ (BIOS)

РЕКОМЕНДАЦИЯ: ПРОФИЛЬ XMP / EXPO И ВСЁ. Ручной разгон памяти НЕ рекомендуем. Соотношение риска и выигрыша плохое: неправильные значения дают нестабильность, BSOD и тихую порчу данных, а прирост поверх нормального профиля обычно в пределах погрешности.

  • XMP / DOCP / EXPO -> Enabled, профиль из SPD модуля
  • Больше ничего не менять

ЕДИНСТВЕННОЕ ИСКЛЮЧЕНИЕ - КРИВОЙ ПРОФИЛЬ. Бывает, что профиль выставляет частоту с отклонением на мегагерц или плата сама поднимает BCLK, и память оказывается чуть выше номинала. Симптомы: ошибки в тестах при "правильных" настройках, редкие вылеты.

  Что делать в этом случае:
  [ ] DRAM Frequency -> выставить РОВНО номинал профиля (6000, не 6001)
  [ ] BCLK           -> 100.0, если плата его подняла
  [ ] Тайминги и напряжения НЕ трогать, оставить из профиля

Проверить фактическую частоту: Диспетчер задач -> Производительность -> Память -> Скорость или ZenTimings / HWiNFO

FCLK вручную имеет смысл только на DDR4 ради синхрона 1:1 (1600 для 3200, 1800 для 3600). На DDR5 не трогать.

Обязательная проверка после любого изменения памяти: [ ] TestMem5 с профилем anta777 extreme -> минимум 1 час -> 0 ошибок [ ] Диспетчер задач -> Производительность -> Память -> Скорость = целевая [ ] Нет BSOD и вылетов игр в течение недели

Если ошибок хоть одна - откатывай. "Работает вроде нормально" на памяти не существует: она молча портит данные.

Порядок важен: сначала стабилизировал память и прогнал тест, только после проверки стабильности отдельно оцени необходимость настроек из раздела 6. Наоборот - закрепишь нестабильную тренировку и получишь редкие BSOD без понятной причины.

8. DNS: ПОДБОР И ПРОВЕРКА. ТОЛЬКО ВРУЧНУЮ

WinPulse НЕ меняет DNS автоматически. Причина: смена DNS ломает локальные сети, captive-порталы провайдеров и может конфликтовать с Zapret.

Что DNS меняет, а что нет:
  Меняет:    скорость резолва имён, фильтрацию, работу блокировок
  НЕ меняет: пропускную способность канала и ping до игрового сервера
             (в игре ты подключаешься по IP, DNS там не участвует)

Кандидаты на тест:

  Провайдер (по DHCP)     базовая точка отсчёта, всегда сравнивай с ним
  Cloudflare              1.1.1.1        1.0.0.1
  Google                  8.8.8.8        8.8.4.4
  Quad9                   9.9.9.9        149.112.112.112   (режет малварь)
  AdGuard DNS             94.140.14.14   94.140.15.15      (режет рекламу)
  OpenDNS                 208.67.222.222 208.67.220.220

Замечания: - AdGuard и Quad9 могут ломать отдельные сайты и сервисы. - Cloudflare обычно быстрый, но с Zapret часть сайтов может открываться заметно дольше. Это не "DNS плохой", это взаимодействие со стратегией обхода. Тестируй именно со своим Zapret. - Два сервера от РАЗНЫХ провайдеров - не резервирование, а лотерея: Windows может ходить к любому. Лучше два от одного.

Как задать (замени "Ethernet" на имя своего адаптера): netsh interface show interface netsh interface ip set dns name="Ethernet" static 1.1.1.1 netsh interface ip add dns name="Ethernet" 1.0.0.1 index=2 ipconfig /flushdns

Как вернуть на автоматический (DHCP): netsh interface ip set dns name="Ethernet" dhcp ipconfig /flushdns

Как замерять (PowerShell, суммарное время 10 запросов): Measure-Command { 1..10 | ForEach-Object { Resolve-DnsName example.com -Server 1.1.1.1 -DnsOnly -Type A } }

Прогони для каждого кандидата и для провайдерского. Сравнивай не одно измерение, а три подряд: кэш и сеть дают разброс.

DoH (шифрованный DNS), Windows 11: Параметры -> Сеть и Интернет -> Ethernet/Wi-Fi -> Назначение DNS-сервера -> Изменить -> вручную -> IPv4 -> ввести адреса -> выбрать "DNS через HTTPS" -> Вкл (автоматический шаблон) DoH добавляет немного задержки, но скрывает запросы от провайдера. С Zapret поведение может измениться - проверяй.

Браузерный DoH: Chrome, Firefox и Edge умеют свой DNS поверх системного. Если в браузере включён Secure DNS, системные настройки для него не работают. При подборе DNS и при диагностике Zapret проверяй и браузерный DoH тоже.

9. ZAPRET / WINWS

WinPulse детектит winws/zapret при запуске и предупреждает перед сетевыми блоками.

ВАЖНО, БЕЗ СМЯГЧЕНИЙ: Zapret ЧУВСТВИТЕЛЕН к изменениям сетевого стека. После сетевых твиков WinPulse он, скорее всего, будет работать ХУЖЕ: часть сайтов перестанет открываться или начнёт грузиться заметно дольше. Это НЕ баг WinPulse и не баг Zapret. Это ожидаемое следствие того, что стратегия обхода подбиралась под прежнее состояние стека.

Правильное лечение: ПЕРЕУСТАНОВИТЬ ZAPRET ИЗ ЕГО СОБСТВЕННОГО МЕНЮ. Не наши net stop / net start, а именно переустановка через меню zapret - она заново применит стратегию под текущий стек.

Порядок действий: 1. net stop winws 2. Применить режим WinPulse 3. Перезагрузка 4. Переустановить Zapret через его собственное меню Конкретные шаги - блок "Своя конфигурация Zapret" ниже 5. Проверить доступность сайтов и скорость на обычных сайтах 6. Если стало хуже - подобрать стратегию заново или откатить сетевые твики: WinPulse -> Rollback -> группа N

Если сетевые твики тебе не нужны, а Zapret критичен: в WinPulse можно откатить только группу N, остальное останется.

Если служба не останавливается (запущена не как служба, а процессом): tasklist | findstr /i winws taskkill /f /im winws.exe

Проверка после: - открываются ли сайты, которые раньше требовали обхода - не деградировала ли скорость на обычных сайтах - нет ли утечек DNS мимо обхода

Если интернет пропал полностью: netsh int ip reset netsh winsock reset ipconfig /flushdns перезагрузка Это сбросит часть сетевых твиков WinPulse - потом прогони режим заново. В WinPulse то же самое есть в [D] Диагностика -> Сброс сети, с подтверждением и пометкой в журнале как необратимой операции.

DNS и Zapret: Часть стратегий чувствительна к DNS. Если после смены DNS сайты стали грузиться дольше - вернись на провайдерский и проверь снова. Список кандидатов и команды в разделе 8.

Своя конфигурация Zapret. GUIDE-COND Проверено автором WinPulse на своём провайдере. Это НЕ универсальный рецепт: стратегия обхода зависит от провайдера, региона и от того, что именно блокируется. Номера пунктов меню привязаны к версии.

Версия и источник: zapret-discord-youtube 1.10.4 от Flowseal https://github.com/Flowseal/zapret-discord-youtube/releases/tag/1.10.4 На другой версии номера пунктов и набор конфигов могут отличаться. Сверяйся с меню, а не с цифрами из этого файла.

Когда это делать: ПОСЛЕ применения сетевых твиков WinPulse и перезагрузки. Этот же порядок используется для переустановки, если Zapret деградировал после твиков.

  Распаковка и первичная настройка:
    [ ] Распаковать архив в папку без символов ! % ^ & в пути
    [ ] Запустить service.bat от администратора
    [ ] Сразу выставить параметры:
          4) Game filter        -> Enabled (TCP and UDP)
          5) Ipset Filter       -> Loaded
          6) Auto-Update Check  -> Disabled

Почему Auto-Update Check выключен: чтобы набор конфигов и стратегия не менялись сами. Обновление может тихо поменять поведение, и ты будешь искать причину в твиках, а не в обновлении. Обновляйся осознанно и с повторным прогоном тестов.

Почему Ipset Filter = Loaded, а не Any: Loaded обрабатывает только адреса из загруженного списка, то есть меньше постороннего трафика попадает под стратегию. Any шире и лечит случаи, когда нужного адреса в списке нет, но и побочек даёт больше. Начинай с Loaded.

Подбор конфига через тесты: [ ] 12) Run tests -> 1) Standart tests -> 1) All configs [ ] Дождаться конца и смотреть ТОЛЬКО на те конфиги, которые прошли ВСЕ проверки, а не часть [ ] Выбрать из прошедших методом исключения

По опыту автора самые стабильные: EXP, 9, 11, 12. Это отправная точка, а не рейтинг. На твоём провайдере может выиграть другой.

Важное про пинг в тесте: разница между конфигами почти отсутствует. Пинг здесь НЕ критерий выбора. Сортируй по факту прохождения всех проверок, а не по миллисекундам.

Почему методом исключения: конфиг может идеально тянуть YouTube и при этом не открывать другой нужный сервис. Проверяй те сервисы, которыми реально пользуешься, а не один удобный для теста.

Финальные шаги после выбора конфига: [ ] 8) Update IPset List [ ] 9) Update Hosts File Zapret сам откроет файл hosts в отдельном окне. Нужно просто скопировать и вставить предложенное содержимое. Ничего придумывать и дописывать руками не надо. [ ] 3) Check Status - убедиться, что служба и фильтры поднялись

Если всё работает штатно - НЕ ТРОГАЙ. Здесь нет "умных настроек на пинг" и скрытых ускорителей. Работающую стратегию менять незачем: любое изменение - это лотерея, а не оптимизация.

Если сайты грузятся плохо - три фикса, строго по порядку: 1. Сменить конфиг на другой из прошедших все тесты. Самый частый и самый безопасный вариант. 2. Ipset Filter -> Any. Расширяет охват, лечит отсутствующие в списке адреса. Побочек больше: под стратегию попадает больше трафика. 3. Убрать или сменить DNS - в браузере или в самой Windows. Браузерный DoH часто перебивает системный DNS и ломает обход. Кандидаты и команды замера - раздел 8 этого файла. Проверь сначала возврат на провайдерский DNS, потом уже подбор.

Меняй по ОДНОМУ пункту и проверяй. Иначе не поймёшь, что помогло. Конфликты бывают редко, но бывают.

Риски и откат: - Zapret ставит драйвер перехвата пакетов. Возможна реакция антивируса и конфликт с другими фильтрами сети, включая корпоративные VPN и антивирусные веб-щиты. - Изменения hosts и установка службы идут МИМО журнала WinPulse. Откат группы N вернёт сетевые твики, но не удалит службу Zapret и не откатит hosts. Для этого - удаление через service.bat и точка восстановления. - Сетевые твики WinPulse и стратегия Zapret связаны. После любого изменения сетевой группы прогоняй тесты заново, а не удивляйся, что вчерашний конфиг перестал работать.

Причины бывают: RAM меньше порога, HDD или неизвестный тип диска, ноутбук, питание от батареи, CPU не того поколения, нет стороннего антивируса, Tamper Protection включён, сборка Windows вне поддержки. Блокировка - не ошибка. Это защита от применения не на своей системе. В виртуальной машине блокировок будет больше, чем на живом железе: виртуальный диск часто отдаёт неизвестный медиатип, а GPU - неизвестный вендор. Это ожидаемо, а не поломка.

Детект показывает не то железо WinPulse -> [K] Починка детекта. Проверит службы Winmgmt и StorSvc, целостность репозитория WMI, повторит опрос через Win32 API. Три канала: WMI, прямой API, реестр. Если все три не дали факт - зависимые твики закрыты, и это правильно.

Defender или SmartScreen заблокировал WinPulse Скрипт меняет BCD и отключает защиту ядра. Эвристика реагирует на такое поведение ожидаемо. Это не ложное срабатывание в смысле "файл чистый": поведение действительно такое. Решай сам, добавлять ли исключение.

Tamper Protection не даёт изменить Defender Сними вручную в Безопасности Windows. WinPulse вернёт FAIL с этой причиной, а не зелёную галочку.

Selftest не пройден при старте Перечислены отсутствующие метки или verb'ы. Файл модуля повреждён или неполный. Восстанови его целиком. Запуск заблокирован намеренно: отсутствующая метка в CALL убивает батник посреди применения твиков.

Кракозябры вместо русского текста Файл сохранён не в той кодировке. .cmd и .bat - UTF-8 БЕЗ BOM, .ps1 и .txt - UTF-8 С BOM, переводы строк CRLF везде. Подробности в README.txt раздел 2.

AMD Adrenalin, профиль игры: [ ] Radeon Anti-Lag -> ВКЛ для DX11/DX12 без Reflex в игре Если в игре есть NVIDIA Reflex или Anti-Lag 2 - используй их, не оба. [ ] Radeon Chill -> ВЫКЛ. Динамически меняет частоту кадров, ломает консистентность frametime. Для соревновательных игр вредно. [ ] Radeon Boost -> ВЫКЛ. Снижает разрешение в движении, картинка плывёт, а прирост FPS оплачен потерей читаемости целей. [ ] Enhanced Sync -> ВЫКЛ. Даёт рывки на границах развёртки. Вместо него: VSync ВЫКЛ плюс ограничение кадров ниже развёртки. [ ] Wait for Vertical Refresh -> Always off [ ] Frame Rate Target Control -> на 3-5 кадров ниже развёртки монитора Стабильный frametime важнее максимального FPS. [ ] Texture Filtering Quality -> Performance [ ] Surface Format Optimization -> ВКЛ [ ] Tessellation Mode -> AMD optimized [ ] Shader Cache -> AMD optimized [ ] Radeon Super Resolution -> ВЫКЛ при нативном разрешении [ ] Image Sharpening -> по вкусу, на FPS почти не влияет

Питание и охлаждение: [ ] Power Limit -> плюс, если охлаждение позволяет. Даёт стабильные частоты [ ] Кривая вентиляторов -> агрессивнее, чтобы не было троттлинга [ ] Undervolt -> осторожно, тестировать стабильность, не копировать чужие

Метрики CPU в оверлее: Задача AMDRyzenMasterSDKTask запускает cpumetricsserver.exe, который известен как источник DPC-задержек. При планах питания с минимальным состоянием процессора 100% метрика загрузки CPU часто показывает неверные значения. Если CPU-метрики не нужны: schtasks /change /tn "\AMDRyzenMasterSDKTask" /disable Оверлей потеряет загрузку CPU, остальные метрики останутся. В журнал WinPulse это не попадает, откатывать вручную через /enable.

NVIDIA Panel, профиль игры: [ ] Low Latency Mode -> Ultra для DX11. Для DX12 и игр с Reflex - Off, Reflex в игре приоритетнее и работает точнее. [ ] Power Management Mode -> Prefer maximum performance, per-game [ ] Threaded Optimization -> Auto [ ] Shader Cache Size -> Driver Default [ ] Vertical Sync -> Off, плюс ограничение кадров при G-SYNC [ ] Max Frame Rate -> на 3-5 ниже развёртки при G-SYNC

[!] Не складывай всё сразу: Anti-Lag плюс Reflex плюс высокий приоритет в Process Lasso плюс ограничение кадров могут дать хуже, чем каждый по отдельности. Меняй по одному и замеряй 1% low.

17. WIFI-АДАПТЕР: НАСТРОЙКИ ПО ВЕНДОРАМ

Почему это не автоматизировано: единых NDIS-ключей для WiFi нет, имена значений различаются у Intel, Realtek, Broadcom и MediaTek. Неверная запись может уронить линк полностью, и ноутбук останется без интернета, чтобы это исправить. Ethernet автоматизирован в блоке NIC_DRIVER, WiFi остаётся ручным сознательно.

Что выставлять и почему: [ ] Roaming Aggressiveness -> Lowest Каждое переключение точки доступа это спайк на сотни миллисекунд. Для стационарного ПК или ноутбука на столе роуминг не нужен. [ ] Preferred Band -> Prefer 5 GHz, ТОЛЬКО при сильном сигнале 5 ГГц хуже проходит стены. Слабее примерно -65 dBm оставляй Auto, иначе стабильность проиграет скорости. Для игр стабильность важнее. [ ] Wireless Mode -> полный набор a/b/g/n/ac/ax, НЕ только новый Форс ax-only или ac-only ломает связь со старым роутером и убирает откат на устойчивый режим на дальней дистанции. [ ] Channel Width 5 GHz -> Auto Форс 80 или 160 МГц упирается в DFS и радарные каналы, даёт разрывы. [ ] Power Saving Mode / MIMO Power Save -> No SMPS, максимум Главный пункт для латентности: энергосбережение усыпляет радиотракт. [ ] U-APSD / WMM Power Save -> ВЫКЛ [ ] Packet Coalescing -> ВЫКЛ. Склеивание пакетов добавляет задержку. [ ] Transmit Power -> Highest [ ] Fat Channel Intolerant -> ВЫКЛ [ ] Bluetooth Collaboration -> ВКЛ только если пользуешься BT на 2.4 ГГц

Имена значений в реестре, ветка адаптера: HKLM\SYSTEM\CurrentControlSet\Control\Class\{4d36e972-e325-11ce-bfc1-08002be10318}\000X

  Intel:      *RoamingPreferredBandType, *RoamAggressiveness,
              *WirelessMode, *ChannelWidth52, *PowerSaveMode, IbssTxPower
  Realtek:    RoamingSensitivity, PreferredBand, WirelessMode,
              PowerSaveMode, Adhoc11n, VHTSupport
  Broadcom:   RoamTrigger, BandPref, PowerSaveMode, WME
  MediaTek:   RoamingAggressiveness, PreferredBand, PSM

[!] Имена меняются между версиями драйвера. Не пиши значение, которого нет: выдуманный ключ драйвер может проигнорировать или неверно интерпретировать. Сначала посмотри, что реально есть:

Get-ItemProperty "HKLM:\SYSTEM\CurrentControlSet\Control\Class\{4d36e972-e325-11ce-bfc1-08002be10318}\0000" | Format-List *

Замени 0000 на номер своей ветки. Найти номер: Get-ChildItem "HKLM:\SYSTEM\CurrentControlSet\Control\Class\{4d36e972-e325-11ce-bfc1-08002be10318}" | ForEach-Object { $p = Get-ItemProperty $_.PSPath; "$($_.PSChildName) $($p.DriverDesc)" }

Надёжнее менять через диспетчер устройств: там драйвер сам показывает допустимые значения, а не даёт записать несуществующее.

18. EFFICIENCY MODE И ECOQOS

Что это: механизм Windows, который помечает потоки фоновых процессов флагом EcoQoS. Планировщик снижает для них частоту и приоритет, чтобы они не отбирали ресурсы у активного окна и не грели пакет.

Вручную: диспетчер задач -> Подробности -> правый клик по процессу -> Эффективный режим. Ставится на процесс, снимается там же.

Почему WinPulse ставит PowerThrottlingOff = 0: Троттлинг действует на ФОН, а не на игру в фокусе. Отключая его, чужие оптимизаторы разрешают апдейтерам, телеметрии и индексатору работать на полной частоте и отбирать CPU у игры. На ноутбуке это ещё и прямой расход батареи. Мы оставляем троттлинг включённым.

Если тебе нужно, чтобы фоновая задача работала на полной скорости, например рендер или энкодер во время игры, снимай эффективный режим с конкретного процесса, а не глобально.

Автоматическая часть в WinPulse: Блок IFEO_ECO выставляет для известных фоновых апдейтеров CpuPriorityClass = 5 (Below Normal), IoPriority = 1, PagePriority = 3 через Image File Execution Options\PerfOptions. Это статическая подсказка планировщику, применяемая при каждом запуске процесса.

Ограничение: IFEO не включает EcoQoS напрямую, флаг ставится процессом через API. IFEO-приоритеты дают похожий эффект, но это не то же самое, что настоящий эффективный режим.

Блок WORK_IFEO делает то же для офисных приложений. Если пользуешься Process Lasso, его правила сильнее и перезапишут приоритет на лету.
