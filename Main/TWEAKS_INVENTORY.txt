Это сверочный документ, не инструкция. Инструкции - в README.txt
и MANUAL_STEPS.txt.

Зачем он нужен:
  1. Каждый блок в коде объявляет ожидание: BLOCK_BEGIN "ИМЯ" N.
     Число N берётся отсюда. BLOCK_END сверяет факт с ожиданием
     и пишет WARN при расхождении. Расхождение = потерянный твик.
  2. При ручной сборке или правке файлов можно пересчитать операции
     и найти, что выпало.
  3. AUDIT.py сверяет суммы в END OF FILE против этого инвентаря.

  LITE      60    MINIMUM 114    MEDIUM  155    WORK  124    MAXIMUM 278

  LIT = LITE   MIN = MINIMUM   MED = MEDIUM   WRK = WORK   MAX = MAXIMUM

 КАК СВЕРИТЬ ФАКТ С ЭТИМ ФАЙЛОМ
---------------------------------------------------------------------------

  1. winpulse.bat /dryrun
     В каждом блоке строка: -- ИМЯ: ok=N fail=N skip=N plan=N
     Сумма должна равняться числу ops из карточки блока.
     WARN про расхождение = потерянная или лишняя операция.

  2. python AUDIT.py
     Сверяет метки, счётчики в END OF FILE, кодировки, карту меню.
     Семантику не проверяет.

  3. WinPulse -> [S] Состояние твиков
     Читает те же пути, куда писал, с нормализацией hex.

  4. WinPulse -> [U] История сессий -> [V]
     Журнал сессии построчно. Число записей может быть БОЛЬШЕ числа
     операций: агрегированные операции (025, 026, 150, 192, 193, 204)
     пишут в журнал по записи на каждый объект, а считаются одной.
