===========================================================================
 W I N P U L S E   7.1   " R E B U I L D "
 Windows 10 22H2 / Windows 11 optimization toolkit
===========================================================================

Начни с WinPulse.exe. В разделе «Начало работы» выбери один из шести режимов. Инструменты доступны отдельно в диагностике, измерениях, обслуживании и конструкторе. Для консольного режима используй winpulse.bat.

---------------------------------------------------------------------------
 0. ТРЕБОВАНИЯ И ОГРАНИЧЕНИЯ. ЧИТАТЬ ПЕРВЫМ
---------------------------------------------------------------------------

Обязательно:
  - Windows 10 22H2 (build 19045) или Windows 11, любая сборка
  - Для окна рекомендуется Windows x64 с .NET Framework 4.8 или новее.
  - Права администратора запрашивает движок при запуске профиля или отката.
  - PowerShell 5.1 (встроен в поддерживаемые версии)
  - Включённая защита системы (System Restore) на системном томе
  - Минимум 2 ГБ свободного места на системном томе

Имя папки любое: WinPulse, WinPulseRelease, как угодно. Путь берётся
из расположения батника, в коде имя папки не зашито.
Ограничение только на символы  !  %  ^  &  в полном пути и на глубину
вложенности. Пример удобного расположения: C:\WinPulseRelease

НЕ поддерживается и заблокировано на старте:
  Windows 7, Windows 8, Windows 8.1, Windows 10 до 22H2,
  Windows Server, LTSC старше 19045.

  Причина не в вредности: в этих системах отсутствует половина
  используемых командлетов и powercfg-алиасов, а часть ключей реестра
  не существует. Применение дало бы десятки ошибок и неизвестное
  состояние вместо оптимизации. WinPulse проверяет сборку и выходит
  до первого изменения системы.

Модули в lib\ НЕ предназначены для прямого вызова. Они требуют
контекста winpulse.bat и без него возвращают код 9009, ничего не делая.
Это защита от применения твиков мимо журнала и точки восстановления.

---------------------------------------------------------------------------
 1. БЫСТРЫЙ СТАРТ
---------------------------------------------------------------------------

  1. Распакуй весь комплект в отдельную папку. Рядом с WinPulse.exe должны быть winpulse.bat, Main и lib.
  2. Запусти WinPulse.exe двойным щелчком. Каталог и справка доступны сразу, без повышения прав.
  3. Открой «Начало работы», выбери режим и оформление. Раскрой «Состав режима» и проверь нужные блоки.
  4. Нажми «Предпросмотр». После запроса прав появится окно сессии WinPulse. В нём видны соглашение, определение ПК, проверки и план режима.
  5. Для реального запуска вернись в окно и нажми «Применить…». Проверь подтверждения и итог в окне сессии. Движок сам предложит перезагрузку, если она нужна.
  6. Для возврата открой «Восстановление», выбери сессию и группу в меню движка. Ручные действия из справки возвращаются отдельно.

Ключи запуска:
  winpulse.bat /dryrun      песочница: только план, без записи в систему
  winpulse.bat /advanced    включить Advanced Mode при старте
  winpulse.bat /?           справка

ПЕРВЫЙ ПРОГОН РЕКОМЕНДУЕТСЯ В ПЕСОЧНИЦЕ:

  winpulse.bat /dryrun

  Что смотреть в выводе:
    - Preflight: все строки [OK], ни одной [FAIL]
    - selftest: ни одного "нет метки" и "нет verb"
    - карта меню: клавиш и пар поровну
    - Detect tier: full или partial. Если registry - часть твиков закрыта
    - В блоках: plan=N совпадает с ожиданием, WARN про расхождение нет
    - Секция "ЗАБЛОКИРОВАНО ЗАЩИТОЙ": причины понятны

  Песочница ничего не пишет в систему и не создаёт точку восстановления.
  Она показывает план и блокировки. Если тут чисто - можно применять.

Кодировки, это важно при правке файлов:
  .bat и .cmd   UTF-8 БЕЗ BOM, CRLF
  .ps1          UTF-8 С BOM, CRLF
  .txt          UTF-8 С BOM

В Notepad++ это два разных пункта меню: "Кодировки -> UTF-8" и
"Кодировки -> UTF-8-BOM". Для .cmd BOM ломает первую строку @echo off,
для .ps1 отсутствие BOM ломает кириллицу.

Комментарии в конце файлов:
  .bat и .cmd   :: END OF FILE
  .ps1          # END OF FILE      двойное двоеточие в PS не комментарий

Символ "!" внутри echo-строк запрещён: его съедает delayed expansion.
Эмодзи и box-drawing не используются: под chcp 65001 не-BMP символы
ломают разбор файла интерпретатором cmd.

                  На слабом ПК визуал идёт в профиле Comfort.

---------------------------------------------------------------------------
 5. ЧТО ИЗМЕНИЛОСЬ ПРОТИВ 6.x
---------------------------------------------------------------------------

Меню и навигация:
  - Было: цифры вперемешку с буквами, каскад if errorlevel, обещанные
    в README клавиши, которых не было в коде.
    Стало: два меню на карте, selftest карты при старте.
  - Новое: матрица защиты [J], починка детекта [K], время загрузки [N],
    история сессий [U], поиск по докам [F], внешние тулзы [Y].
  - Уровень пользователя и туториал для Novice.

Работа:
  - Песочница /dryrun, которой не было вообще.
  - Preflight виден построчно, а не молча падает посреди режима.
  - Selftest меток и verb'ов до первого вызова.
  - Аудит каждого блока: ожидание против факта.
  - Сводка с секцией guard и причинами блокировок.
  - Бенчмарк считает дельту, а не печатает два файла рядом.
  - Настройки реально читаются, а не только сохраняются.

Безопасность:
  - Откат по журналу значений вместо мифического экспорта HKLM.
  - Точка восстановления обязательна, обход только в Advanced.
  - Гейт BitLocker и приостановка защиты перед BCD.
  - Guard fail-closed: неизвестный факт закрывает твик, а не открывает.
  - Профиль визуала Keep.

Техническое:
  - 11 файлов вместо одной простыни.
  - ASCII без эмодзи: под chcp 65001 они ломали разбор файла.
  - Админ через fltmc, корректный Sysnative-перезапуск, лок в .run.

Исправлены твики, которые в 6.x были пустышками:
  Nagle в корень Tcpip вместо Interfaces\{GUID}, SmoothMouseCurve
  длиной 32 байта вместо 40, MinAnimate не в той ветке, MSI и GameBar
  через Access Denied, ULPS и HDCP в слепой 0000, фиктивный ключ
  аудио-улучшений, несуществующий параметр MemoryTrim, чистка TEMP
  в профиль админа, FontCache при живой службе, useplatformtick
  yes и no в одном прогоне.

---------------------------------------------------------------------------
 6. БЭКАП И ОТКАТ. КАК ЭТО РАБОТАЕТ НА САМОМ ДЕЛЕ
---------------------------------------------------------------------------

В версии 6.x README обещал автоматический экспорт HKLM объёмом 100-300 МБ
при каждом запуске. Этого экспорта в коде не было никогда. Меню
восстановления листало пустую папку, а сводка печатала неинициализированную
переменную. В 7.0 механизм другой и он реальный.

Журнал значений:
  Перед каждой записью обёртка читает текущее значение и пишет в
  Backups\<метка>\journal.txt строку вида:
    ТИП|ключ|значение|прежнее состояние
  Если значения не было, пишется ABSENT, и откат его удалит.

  Всего 19 типов записей: реестр, реестр под TrustedInstaller, ключи,
  службы, BCD, питание, схема питания, созданная схема, netsh, supplemental,
  fsutil, задачи, гибернация, Reserved Storage, приостановка BitLocker,
  MMAgent, исключения Defender, состояние Defender, необратимое.

Откат:
  [O] -> выбрать сессию -> выбрать группу.
  Записи обходятся в ОБРАТНОМ порядке. Если значение менялось дважды
  за сессию, последним восстановится самое первое, то есть настоящее "до".
  Откат пишет в свой лог, а не в журнал сессии, и не плодит новые записи.

Что откат вернёт:
  значения реестра, состояние служб, элементы BCD, индексы питания,
  активную схему, удалит созданную схему Ultimate, вернёт гибернацию
  вместе с hiberfil.sys, вернёт Reserved Storage, включит защиту BitLocker,
  вернёт MMAgent, исключения и состояние Defender, включит задачи.

Что откат НЕ вернёт:
  удалённые UWP-приложения (список и команда переустановки лежат
    в Backups\<метка>\appx_removed.txt)
  удалённые файлы после чистки TEMP и кэшей
  salvage репозитория WMI
  сброс сетевого стека через winsock reset
  всё, что сделали сторонние оптимизаторы

Необратимое показывается в итоге отката отдельным списком, а не прячется
за зелёной галочкой.

Честные ограничения отката:
  netsh и задачи планировщика возвращаются к документированным дефолтам
  Windows, а не к вашему прежнему состоянию: оно не читается
  locale-независимо.
  Если прежнее состояние определить не удалось, в журнал пишется UNKNOWN
  или -1, и откат такой пункт ПРОПУСТИТ с пометкой "верни вручную".
  Он не угадывает.

Точка восстановления:
  Создаётся принудительно перед каждым режимом. Успехом считается
  только найденная точка с нашим описанием, а не "команда не упала".
  Не создана -> режим не запускается.
  Обход возможен только в Advanced Mode вводом слова SKIP, с записью
  в лог и постоянной меткой в шапке меню.
  Лимит 24 часа и запрет System Restore снимаются через обёртки, то есть
  попадают в журнал и откатываются вместе со всем остальным.
  Отключённые VSS и swprv переводятся в Manual, попытка повторяется.

---------------------------------------------------------------------------
 7. ЗАЩИТА ОТ НЕПОДХОДЯЩЕЙ СИСТЕМЫ
---------------------------------------------------------------------------

Три уровня:
  HARD   твик не применяется, обхода нет даже в Advanced
  SOFT   нужен Advanced Mode и ввод YES заглавными
  INFO   тихий пропуск: твик не для этой конфигурации

Главный принцип: неизвестно = нельзя. Провал детекта ЗАКРЫВАЕТ твик.
В 6.x было наоборот: упавший Get-PhysicalDisk давал HDD_COUNT=0,
из этого следовало ALL_SSD=1, и дефраг отключался на HDD.

Примеры жёстких блокировок:
  SysMain OFF и defragsvc OFF   требуют все диски SSD, без неизвестных
  Kernel Paging combo           требует 32+ ГБ, рекомендуется 64+
  Memory Compression OFF        требует 32+ ГБ
  CPU C-states OFF              только десктоп и только питание от сети
  Ultimate Performance          только десктоп и только питание от сети
  Heterogeneous scheduling      требует реальные E-cores и Win11
  TSC sync Legacy               запрещён Intel 12+ и Ryzen 5000+
  Defender Realtime OFF         требует сторонний антивирус
  MSI Mode GPU                  требует определённый instance path
  Любой режим                   требует поддерживаемую сборку Windows

Блокировки видны в сводке отдельной секцией с причинами. Твик не
"пропал", а осознанно не применён. Это разные вещи, и в 6.x они
выглядели одинаково.

[J] Матрица защиты показывает факты вашей системы против порогов
и вердикт по каждому ключевому твику: OK, ASK или BLOCK. Она вызывает
настоящие проверки, а не копию их условий, поэтому пороги не разъезжаются.

         IOCTL_STORAGE_QUERY_PROPERTY (seek penalty),
         IOCTL_VOLUME_GET_VOLUME_DISK_EXTENTS, DriveInfo,
         реестр для GPU и CPU
Канал 3  только реестр и переменные окружения, без PowerShell

Канал 2 запускается только когда чего-то реально не хватает. Слияние
не перезаписывает валидный факт худшим каналом. Каждый факт несёт
пометку источника: wmi, api, registry, smbios, none.

DETECT_TIER: full, partial, api, registry. Виден в шапке и в матрице.

Деградация детекта НЕ блокирует режим целиком. Телеметрия, задачи,
UX и службы применятся даже в registry-tier. Закроется только то,
что зависит от недостающего факта.

[K] Починка детекта проверяет службы Winmgmt и StorSvc, целостность
репозитория WMI, включает отключённые службы через обёртку с журналом
и повторяет опрос. Salvage репозитория требует ввод YES и помечается
необратимым.

Определение версии: семейство берётся из build, а не из ProductName.
В реестре Windows 11 до сих пор написано "Windows 10 Pro" - это не баг
WinPulse, это особенность самой Windows.

---------------------------------------------------------------------------
 9. БЕНЧМАРК И ВРЕМЯ ЗАГРУЗКИ
---------------------------------------------------------------------------

[G] Бенчмарк:
  быстрый около 10 секунд, полный около 30
  CPU в один поток и во все, копирование памяти, запись и чтение диска,
  ping и DNS-резолв

  Замеры хранятся как KEY=VALUE, поэтому сравнение считает дельту
  численно и знает направление метрики: для миллисекунд меньше значит
  лучше, для MB/s наоборот.
  Порог 5 процентов: ниже выдаётся NOISE, а не "прирост".
  Сравнение предупреждает, если профили разные или CPU отличается.

  Честные ярлыки: индекс CPU относительный, это не Cinebench.
  Чтение диска помечено cached, кэш ОС участвует, это не CrystalDiskMark.
  Запись идёт с WriteThrough.

  При включённой настройке "Замер до/после" режим сам делает baseline
  перед применением и final после, и показывает дельту в сводке.
  Замер "после" идёт ДО предложения перезагрузки.

[N] Время загрузки:
  Читает журнал Diagnostics-Performance, событие 100:
  BootDuration, MainPathBootTime, BootPostBootTime в миллисекундах.
  События 101/102/103 называют конкретные приложения, драйверы и службы,
  которые тормозили загрузку, с временем каждое.
  Именно BootPostBootTime растёт от автозагрузки.
  POST в эти цифры не входит: он происходит до загрузчика Windows,
  поэтому эффект BIOS-настроек надо замерять отдельно.

  Если журнал отключён, экран покажет команду его включения.

---------------------------------------------------------------------------
 10. ЧЕГО WINPULSE НЕ ДЕЛАЕТ
---------------------------------------------------------------------------

Не делает и не будет:
  - BIOS/UEFI: C-states, ReBAR, XMP/EXPO, PBO, LLC, Fast Boot, CSM
  - настройки сетевого адаптера в драйвере (имена параметров разные)
  - per-device галки энергосбережения USB
  - отключение устройства HPET в диспетчере устройств
  - смену DNS-серверов (нужен выбор по замерам, см. MANUAL_STEPS)
  - настройку Zapret/winws
  - чистку автозагрузки (запланировано, см. раздел 14)
  - debloat браузеров
  - запуск сторонних оптимизаторов

Последнее принципиально: irm christitus.com/win | iex выполняет
произвольный удалённый код с правами администратора, содержимое которого
меняется без вашего ведома. Место таким вещам - в документации
с явным предупреждением, а не внутри батника.

После MAXIMUM сторонние тулзы всё равно найдут около десятка непокрытых
пунктов. Это нормально: WinPulse закрывает то, что можно журналировать
и откатить, а не всё подряд. Сверка по пунктам - в EXTERNAL_TOOLS.txt.

Категория GUIDE:
  Настройки GUI, BIOS и приложений, которые WinPulse не применяет,
  не журналирует и не считает в 292. Они живут в MANUAL_STEPS.txt
  с градацией: GUIDE-SAFE, GUIDE-COND, GUIDE-FIX, GUIDE-AVOID.
  У каждого пункта указано что даёт, чем рискован и как вернуть.

---------------------------------------------------------------------------
 11. ПРОВЕРКА ЦЕЛОСТНОСТИ
---------------------------------------------------------------------------

Встроенная проверка при каждом старте:
  - наличие всех модулей и wp.ps1
  - наличие всех входных меток, на которые есть вызовы
  - наличие всех verb'ов PowerShell
  - соответствие строки клавиш и карты меню
  При любом отсутствии запуск блокируется с перечислением. Это сделано
  потому, что отсутствующая метка в CALL убивает батник целиком, и лучше
  узнать об этом на старте, чем посреди применения твиков.

Внешняя проверка, необязательная:
  python AUDIT.py [путь_к_папке]

  Проверяет то, что решаемо механически: кодировки и BOM, переводы строк,
  дубли меток, битые вызовы, остатки маркеров продолжения, счётчики
  в END OF FILE, карту меню, не-ASCII графику в bat-файлах.
  Полезно после ручной сборки или правки файлов.

  Семантику твиков AUDIT не проверяет: для этого есть /dryrun
  и самоаудит блоков в рантайме.

---------------------------------------------------------------------------
 12. ИЗВЕСТНЫЕ ПРОБЛЕМЫ
---------------------------------------------------------------------------

Selftest не пройден, перечислены отсутствующие метки
  Файл модуля повреждён или неполный. Восстановите его целиком.
  Запуск заблокирован намеренно.

Карта меню рассинхронизирована
  Строка клавиш и карта пар не совпадают. Такое бывает после ручной
  правки меню. Сверьте AM_KEYS/AM_MAP или NV_KEYS/NV_MAP в winpulse.bat.

Недопустимые символы в пути
  Уберите ! % ^ & из полного пути. Проще всего C:\WinPulseRelease

Интернет пропал на 10-30 секунд после сетевых твиков
  Нормально: стек перестраивается. Дольше - ipconfig /flushdns.

Zapret стал работать хуже, сайты грузятся дольше
  Ожидаемо. Стратегия обхода подбиралась под прежнее состояние стека.
  Переустановите Zapret из его СОБСТВЕННОГО меню, а не через net stop/start.
  Не помогло - откат группы N. Проверенный порядок настройки - в
  MANUAL_STEPS раздел 9.

Windhawk выглядит плоским, анимации деревянные
  Моды работают, изменён только внешний вид. Выберите профиль Keep
  при запуске MAXIMUM, либо верните стекло командами из MANUAL_STEPS
  раздел 11, либо откат группы V.

Артефакты на экране после MAXIMUM или Experimental
  Возможен DWM OverlayTestMode=5. Откат группы G, либо удалить значение
  и перезапустить DWM (команды в MANUAL_STEPS).

Печать не работает
  Отключён Spooler. Откат группы U, либо sc config Spooler start= auto.

FaceIT / ESEA не запускаются
  Античиты требуют VBS. Откат группы S, либо режим WORK вместо MAXIMUM.

Netflix / Disney+ не работают
  Отключён HDCP для NVIDIA. Откат группы G, перезагрузка.

Game Pass и игры из Store не авторизуются
  Отключены службы Xbox. Откат группы U.

Windows Update вернул VBS
  Обновления восстанавливают защиту. Это не баг WinPulse. Решите,
  что важнее, либо применяйте блок заново после крупных обновлений.
  Именно поэтому обновления ставятся ДО твиков, а не после.

BitLocker просит ключ восстановления
  Правки BCD меняют измерения TPM. WinPulse приостанавливает защиту
  на одну перезагрузку перед BCD-блоками, но ключ должен быть сохранён
  заранее. Стартовый гейт показывает команду его получения.

Твик написан BLOCK
  Это guard, а не ошибка. Откройте [J] матрицу защиты: там факты
  против порогов и причина.

Детект показывает не то железо
  [K] Починка детекта. Проверит службы и репозиторий WMI, повторит
  опрос через Win32 API.

Defender или SmartScreen заблокировал WinPulse
  Скрипт меняет BCD и отключает защиту ядра. Эвристика реагирует
  на такое поведение ожидаемо. Это не ложное срабатывание в смысле
  "файл чистый": поведение действительно такое. Решайте сами,
  добавлять ли исключение.

Tamper Protection не даёт изменить Defender
  Снимите вручную в Безопасности Windows. WinPulse вернёт FAIL
  с этой причиной, а не зелёную галочку.

Кракозябры вместо русского текста
  Файл сохранён не в той кодировке. См. раздел 2. Для .cmd нужен
  UTF-8 БЕЗ BOM, для .ps1 и .txt - С BOM, переводы строк CRLF.

 13. ПУБЛИКАЦИЯ И ПРИВАТНОСТЬ
---------------------------------------------------------------------------

Код персональных данных не содержит. Всё личное генерируется
в рантайме в Backups\, Logs\ и .run\:
  имя пользователя и компьютера, SID, модели железа, instance path GPU,

Git-история необратима: удаление файла позже не убирает его из коммитов.
Наиболее чувствительное - список исключений Defender в связке с именем

Репозиторий и релиз - разные вещи:
  В репозиторий кладите файлы как есть, не архив: смысл git в диффах.
  В Releases прикладывайте zip, собранный из папки ЦЕЛИКОМ, чтобы

  без него git нормализует переводы строк и батники перестанут работать.

  К релизу полезно приложить SHA256:
    certutil -hashfile WinPulse-7.1.zip SHA256

  Предупредите пользователей: архив надо РАСПАКОВАТЬ, запуск из

  на скачанный скрипт ожидаема.

Сам WinPulse телеметрии не содержит, наружу не ходит, сторонних

---------------------------------------------------------------------------
 15. ОТКАЗ ОТ ОТВЕТСТВЕННОСТИ
---------------------------------------------------------------------------

WinPulse - инструмент, а не волшебство.

  - Прирост не гарантирован. Разница меньше 5 процентов на повторяемых
    замерах - это шум, а не эффект.
  - Часть твиков снижает защиту системы. Это указано у каждого.
  - Точка восстановления обязательна. Не отключайте System Restore.
  - Откат вернёт значения, но не удалённые файлы и приложения.
  - Сторонние оптимизаторы пишут мимо журнала, применяйте их после.
  - Сначала обновления Windows, BIOS и драйверов, потом твики.

Автор не несёт ответственности за потерю данных, поломку оборудования,
нестабильность системы, несовместимость с другим ПО и блокировки
античитами.

Программа полностью бесплатна. Телеметрии, рекламы и скрытых
загрузок нет.

Правило оценки эффекта: оставляйте только то, что дало измеримый
результат на ВАШЕЙ системе. Твик, который помог кому-то на форуме,
вам может не дать ничего или сделать хуже.

---------------------------------------------------------------------------
 СПРАВКА И ДАННЫЕ ДЛЯ НАСТОЛЬНОГО ИНТЕРФЕЙСА
---------------------------------------------------------------------------

Открой Main\Help\overview.html в браузере. Слева направо в навигации идут обзор, ручные настройки, сторонние утилиты и каталог. В каталоге доступен поиск по операции, блоку и параметру.
build_help.py собирает HTML и catalog.json из документов и lib\blocks.cmd. После изменения источников выполни python -B build_help.py и python -B AUDIT.py. Команда python -B build_help.py --check проверяет актуальность готовых файлов без перезаписи. В релиз включай всю Main\Help.

Контракт чтения, версия 1. Окно работает под учётной записью вошедшего пользователя. Для загрузки списка запускай Windows PowerShell 5.1 без повышения, читай JSON из stdout в UTF-8, проверяй exit code и readErrors.
  powershell -NoProfile -File Main\DesktopData.ps1 -View Startup
  powershell -NoProfile -File Main\DesktopData.ps1 -View Background
Для перехода к конкретному приложению повтори Background с -OpenPackage и PackageFamilyName из списка. В Windows 10 открывается общий список, в Windows 11 — страница выбранного пакета. Доступность фонового разрешения определяет сама Windows. У обычных программ Win32 фон настраивается в самой программе. Изменения в параметрах Windows возвращаются там же.
У автозагрузки поле registered означает наличие записи в источнике. Это не подтверждение запуска при последнем входе. Поля location и name сохраняются полностью; command служит для просмотра. В журнал и телеметрию интерфейса команды не отправлять.
WinPulse.exe читает локальный каталог и руководства. Списки приложений, дисков, загрузок Windows и точек восстановления загружаются по запросу. Для диагностики, обслуживания и действий с настройками используются исходные модули из lib. Предпросмотр, применение и откат открывают окно сессии WinPulse с запросом прав Windows. Вердикты, выбор блоков, вопросы и отчёт доступны в этом окне. Сеанс можно завершить на вопросе движка. Уже выполненные изменения сохраняются в журнале. «Состав режима» в окне показывает номинальный список до гвардов.
Сборка из исходников: powershell -NoProfile -ExecutionPolicy Bypass -File Desktop\build.ps1
Проверка окна без применения настроек: WinPulse.exe --dry-run
Интерфейс поставляется вместе с Main, lib и winpulse.bat. Для передачи другому пользователю собери чистую папку комплекта, сохрани свои Backups и Logs отдельно.
